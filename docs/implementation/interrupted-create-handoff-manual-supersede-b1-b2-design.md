# B1/B2 design review — operator-superseded interrupted handoff

**Disposition (2026-10-05): DESIGN ONLY; B1/B2 BLOCKED, no implementation PASS or owner sign-off.** This is the project-owned review of the [active plan](../../../../.roo/interrupted-create-handoff-manual-supersede-proposal.md:1) and [Package A audit](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:1), not a live-state eligibility assessment. The operator accepts an **UNKNOWN prior-child outcome** and chooses to abandon the old handoff; this is neither proof that no child existed nor permission to override a known child owner. Historical P1/P2/P3 acceptance and v2 intake gates do not apply ([plan](../../../../.roo/interrupted-create-handoff-manual-supersede-proposal.md:3), [A disposition](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:9)). Only this report is created; no source, tests, scaffolds or architecture files are changed.

[atomicReadAndUpdate](../../src/core/task-persistence/TaskHistoryStore.ts:1018) starts with cache, while [paired update](../../src/core/task-persistence/TaskHistoryStore.ts:1036) warns that first-file commit may survive second-file failure. [Disk delta validation](../../src/core/task-persistence/taskStoreConcurrency.ts:23) protects status transition, not old-action/question/child equality; the [ordinary lifecycle table](../../src/core/task-persistence/taskLifecycle.ts:6) rejects interrupted to active. ## Proposed exact-action boundary (requires independent proof, not a claim of enforcement today)

1. **Exceptional entry, not ordinary resume.** Explicit operator confirmation names canonical root, parent and _old action ID_, says prior child outcome UNKNOWN, and elects abandonment. Independently establish predecessor host/process exit and absence of surviving in-flight start/write, restarted loaded build and canonical storage root; inspect current parent, lineage, pending question, authoritative API history and **known** child owner/registry/intent evidence. A disappeared socket, old bundle, time-limited scan or caller assertion is insufficient ([plan](../../../../.roo/interrupted-create-handoff-manual-supersede-proposal.md:5), [A audit](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:18)). Unknown historical child outcome alone is accepted; positive awaited/delegated/active or matching-action child, conflicting registry/intent, or unresolved attribution capable of masking a known owner BLOCKS. Do not require complete-negative child enumeration, invent absence from missing transient metadata, or alter historical child IDs. Surviving equivalent same-parent queue item is resolved using ordinary controls before later new intake, never claimed by B ([plan](../../../../.roo/interrupted-create-handoff-manual-supersede-proposal.md:9)).
2. **Narrow exclusion across both files and all capable writers.** Before inspecting and through B1 append/read-back and B2 repair/read-back, enforce a per-canonical-root/parent exclusion that every competing provider prepare/commit/start, direct/resumed start, startup intent/reconcile, pending action/question/history writer and API snapshot writer either participates in or demonstrably cannot bypass. A competing child cannot prepare under a pre-check and start after B1; it must revalidate or be excluded at prepare, ownership commit **and** schedule. Cross-process/host participation, predecessor drain and loss-of-lease fail-closed semantics must be proven; do not treat a process-local transition, a file lock on only one file, P2's optional [fence](../../src/core/task-persistence/parentHandoffFence.ts:124), or check-then-write as a transaction. Scope only this parent and its old action; unrelated chats/questions must not be globally locked ([provider gap](../../src/core/webview/ClineProvider.ts:3919), [startup gap](../../src/core/task-persistence/TaskHistoryStore.ts:118), [A bypass list](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:26)). If a capable same-parent writer/start cannot be excluded or prevented from a post-check stale save, **BLOCKED: ship A only**.
3. **Authoritative compare at each write.** Under the exclusion, re-read strict canonical root/parent and the actual API file. Require identical _complete_ saved create-subtask action (ID, kind, mode, message, todos, approval text), interrupted status, unchanged parent/root lineage, absent pending question and current awaited/delegated owner, and no new matching-action/known active child. Verify one uniquely identified terminal assistant `new_task` tool-use with exact ID and input corresponding to the saved action; check full effective role/order including siblings, orphan/duplicate results and any later turn/action. A different saved action, later call/result or unresolved sibling is conflict, not something to repair. Before append, the exact call has no result; after append, exactly one approved correlated result immediately resolves it and no later competing turn exists. Raw scanner eligibility is insufficient ([scanner](../../src/core/task-persistence/interruptedCreateHandoffEligibility.ts:137), [saved action](../../src/core/tools/NewTaskTool.ts:105)). The provider/persistence owner must validate the actual provider-effective serialization and fingerprint rules; an unproven effective-history projection is **UNKNOWN/BLOCKED**.

## B1 — one non-success result, no execution

**Proposed transaction boundary:** a dedicated conditional API-file operation (not the ordinary snapshot [save](../../src/core/task-persistence/apiMessages.ts:135)) re-reads/validates exact terminal call, entire result boundary and unchanged owner under the same-parent exclusion, and appends exactly one _user-role_ `tool_result`, `tool_use_id = old action ID`, `is_error = true`, with a stable approved correlation marker/fingerprint tied to canonical root + parent + old action + operator supersession and fixed truthful content: **“operator superseded this handoff; earlier child outcome unknown; this resolution did not start a child.”** The marker must be unambiguously recognizable in persisted/effective history without trusting only a same-ID `is_error`; owner to specify format and deterministic matching of IDs/metadata. Do not write a new user instruction, feedback turn, queue receipt, child start or request loop ([legacy contrast](../../src/core/task/Task.ts:2932), [plan](../../../../.roo/interrupted-create-handoff-manual-supersede-proposal.md:16)).

**Commit ambiguity:** after success _or_ any save error (including post-rename exception), fresh strict read-back under exclusion: one exact correlated result with no changed boundary means B1 committed/already committed; no result with stable unchanged preconditions permits only a newly authorized conditional attempt, never blind retry; missing/unreadable history, differing marker/content, duplicate/success result, changed action or later turn means BLOCK/UNKNOWN, not a second append. Re-enter after crash with the exact result: go to B2 only; no B1 re-append. A matching result is evidence of this resolution's persisted shape, **not** evidence that no prior child existed or guarantee of power-loss durability ([rename](../../src/utils/safeWriteJson.ts:140), [ordinary retry](../../src/core/task/Task.ts:1431)).

## B2 — conditional repair only; restart discriminator

**Proposed repair:** with the same exclusion and strict read-back of exactly one authoritative B1 result, recheck the same parent/action/root/status/question/known owner and unchanged API tail at the metadata write point. A _dedicated fresh disk-under-lock conditional writer_ changes only the still-owned old `pendingAction` to absent and performs a named, narrowly reviewed administrative `interrupted -> active` repair; all other metadata, including `childIds`, completed-child summaries and lineage, stays unchanged. No blanket transition-table relaxation or cached [provider clear](../../src/core/webview/ClineProvider.ts:803)/[atomicReadAndUpdate](../../src/core/task-persistence/TaskHistoryStore.ts:1018). Read back both files and legal status/unchanged history before displaying **ready for a separate new message**. Status alone is not readiness. For this B-marked result, suppress [hydration's generic result-based clear](../../src/core/task/Task.ts:2675) until this discriminator has run; do not hide a pending question or start the [legacy loop](../../src/core/task/Task.ts:2971).

| Restart / concurrent state                                                                                                                                          | Proposed action                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact one B1 result + same interrupted parent, same full old action, no question/known owner/later API turn                                                         | Repair metadata **only**, read back; never add a second result/turn or run a request.                                                                                                       |
| Exact B1 result + metadata already repaired to active with old action absent and unchanged lineage/owner/API boundary                                               | Read back and return already-done; never repeat result or write.                                                                                                                            |
| No result + old action                                                                                                                                              | B2 refuses; B1 needs separate explicit confirmation and guards.                                                                                                                             |
| Known active/delegated/awaited or matching-action child, changed action/status/root, pending question, later call/turn or conflicting/uncorrelated/duplicate result | Block and preserve state; known child goes through ordinary child handling, question through question handling, other conflicts through reviewed reconciliation. No override or new intake. |
| Metadata write error after possible commit, failed read-back or competing write during restart                                                                      | Re-read both under exclusion; exact repaired state is already-done, exact result plus unchanged old state is repair-only retry, otherwise UNKNOWN/BLOCKED.                                  |

This two-file sequence is **not atomic**: B1 result can exist while metadata remains interrupted. B2's recovery-only discriminator is the deliberate reconciliation, not a second API write. No future chat text is delivered by B; subsequent C is a separate ordinary user message whose persistence must be checked separately ([plan](../../../../.roo/interrupted-create-handoff-manual-supersede-proposal.md:17)).

## Hostile-case tests to require before integration (proposals; no fresh tests run)

- B1: missing/corrupt API, wrong/duplicate/nonterminal tool ID, mismatched saved input, sibling unresolved or orphan result, result in wrong role/order, later assistant/user turn, prior success/error-without-marker, duplicate/conflicting marker; _do not_ accept caller-supplied completeness as evidence. Test explicit UNKNOWN prior-child outcome without claiming child absence, plus positive matching-action/awaited/delegated/active child and ambiguous intent/registry that could conceal an owner ([A examples](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:11)).
- Two independent instances and failure injection: old provider paused after [fresh check](../../src/core/webview/ClineProvider.ts:3919), after child prepare but before [ownership commit](../../src/core/webview/ClineProvider.ts:4093), and before [schedule](../../src/core/webview/ClineProvider.ts:4159); direct [createTask scheduling](../../src/core/webview/ClineProvider.ts:3548), startup replay/reconcile and stale API/history writer after B pre-read must be blocked or revalidated. Model host exit/no surviving writer and lease-loss rejection; unrelated parent/question must remain unblocked. A cooperative P2 fence test is not this proof ([A audit](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:12)).
- B1 injected disk rename-commit then thrown error; first read-back fails, then restart; exact result converges to one result, conflicting result never overwritten, no blind append. B2 injected metadata commit then error, metadata no-commit error, crash after API but before metadata, restart with already-repaired state, changed action, pending question and new child between pre-read and metadata lock, startup/hydration interleavings. Assert exactly one result, legal one-off lifecycle, unchanged child IDs/summary, no queue/message/model/child effects, and no premature ready signal ([A split](interrupted-create-handoff-manual-supersede-a-boundary-audit.md:28)).
