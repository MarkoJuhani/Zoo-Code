## Explicit P3 target decisions and separate delivery verdicts

### Host-issued binding and fenced capability

**Target: AGREE. Current delivery: DISAGREE.** P2/host issues and durably reads back the immutable action incarnation after fresh lineage/action validation under the outer parent fence; the UI supplies a stable submission ID, never its own action generation. Rebinding retains generation only for the identical action fingerprint and lineage. P2 hands P3 a scoped capability carrying the separate `actionGeneration`, `fenceGeneration` and `ownerToken`; each journal/blob mutation checks binding, ownership and expected revision atomically with its write, or blocks if this cannot be guaranteed ([P1 binding](../architecture/interrupted-create-handoff-recovery-p1-contract.md:10), [P1 epochs](../architecture/interrupted-create-handoff-recovery-p1-contract.md:24), [P2 target](interrupted-create-handoff-recovery-p2-interface-review.md:21), [P2 capability](interrupted-create-handoff-recovery-p2-interface-review.md:31)). The current [fence lease](../../src/core/task-persistence/parentHandoffFence.ts:27), [host store port](../../src/core/task-persistence/recoveryIntake.ts:13) and [UI helper](../../webview-ui/src/utils/recoverySubmission.ts:20) do not issue/transport this durable binding or enforce an atomic conditional writer ([historical P3 finding](interrupted-create-handoff-recovery-p3-interface-review.md:21)).

### Protected journal/blobs, digest and exact attachments

**Target: AGREE. Current delivery: DISAGREE overall (digest primitive only: AGREE).** P3 accepts only a versioned per-parent journal retaining an immutable acceptance projection with monotone progress revisions and protected immutable text/ordered image-byte blobs; enforce safe paths, permissions, atomic sync/publication, retention and authoritative byte/digest read-back before receipt. `payloadDigest` remains lowercase SHA-256 of the specified fixed-order binding/submission/origin/timestamp/text/ordered canonical-image JSON preimage, not a decoded-byte-only hash or a secret. Resolve **every** original attachment all-or-nothing to exact validated MIME/bytes/canonical base64 before hashing; preserve order/multiplicity, fail closed on skip/truncation/unavailable source, and reconstruct the same preimage from durable blobs ([P1 record and canonical interface](../architecture/interrupted-create-handoff-recovery-p1-contract.md:15), [P1 storage and limits](../architecture/interrupted-create-handoff-recovery-p1-contract.md:17), [P2 handoff](interrupted-create-handoff-recovery-p2-interface-review.md:68)). The [shared serializer](../../src/shared/recoveryIntake.ts:44) agrees at the identity-preimage layer, but its [accepted projection](../../src/shared/recoveryIntake.ts:26) and [candidate host validation](../../src/core/task-persistence/recoveryIntake.ts:57) do not constitute protected blobs or exact-source resolution; the [historical review](interrupted-create-handoff-recovery-p3-interface-review.md:29) separates digest agreement from [attachment](interrupted-create-handoff-recovery-p3-interface-review.md:35) and [storage](interrupted-create-handoff-recovery-p3-interface-review.md:43) gaps.

### Later-state receipt replay

**Target: AGREE. Current delivery: DISAGREE.** Under the parent fence, consult the immutable journal acceptance projection for an exact ID/binding/digest/payload **before** classifying new intake. Validate original lineage, protected bytes and stage-specific correlation/ownership; return the original `acceptedVersion` receipt after `api_committed`, metadata repair, scheduling or action clear without a second acceptance, API append, question answer or loop ([P1 replay](../architecture/interrupted-create-handoff-recovery-p1-contract.md:11), [P2 replay boundary](interrupted-create-handoff-recovery-p2-interface-review.md:79)). Current [intake](../../src/core/task-persistence/recoveryIntake.ts:97) classifies first and [matching](../../src/core/task-persistence/recoveryIntake.ts:70) accepts only `accepted`, so lost-receipt replay after repair is unimplemented ([historical P3 finding](interrupted-create-handoff-recovery-p3-interface-review.md:49)).

### Queue, UI and pending-question ownership

**Target: AGREE. Current delivery: DISAGREE.** P3 persists an immutable client submission snapshot before post and reuses its ID/payload after reload; for an existing queue item, adopt its original ID, timestamp, order and payload **before** claim, bind through P2, and reject accepted-item edit/cancel except by a new submission. Clear only unchanged UI input after its matching durable-read-back receipt; intake never removes a queue item as delivery proof. An exact pending question owns its task/question-ID answer route and takes precedence over new recovery intake, including asynchronous races; replay only acknowledges the earlier accepted submission ([P1 intake/queue](../architecture/interrupted-create-handoff-recovery-p1-contract.md:7), [P1 receipt](../architecture/interrupted-create-handoff-recovery-p1-contract.md:9), [P1 local ack](../architecture/interrupted-create-handoff-recovery-p1-contract.md:18), [P3 review alternatives](interrupted-create-handoff-recovery-p3-interface-review.md:55), [question ownership](interrupted-create-handoff-recovery-p3-interface-review.md:61)). The [UI helper](../../webview-ui/src/utils/recoverySubmission.ts:20) requires caller persistence and its [receipt matcher](../../webview-ui/src/utils/recoverySubmission.ts:44) is unwired; [queue adoption](../../src/core/task-persistence/recoveryIntake.ts:125) is only a snapshot primitive. The [P3 phase matrix](interrupted-create-handoff-recovery-p3.md:59) still blocks real UI/queue/question integration.

### Lock order

**Target: AGREE. Current delivery: DISAGREE.** The P2 coordinator acquires the outer `(globalStoragePath,parentTaskId)` interprocess fence before any inner lock, then holds **only one** inner lock at a time in journal/payload -> API -> journal -> authoritative metadata -> journal order; never acquire outer while holding inner. P3 owns only intake journal/blob stages, not API/repair/schedule, and blocks on unknown peer writers or unsupported fencing ([P1 order and writer participation](../architecture/interrupted-create-handoff-recovery-p1-contract.md:22), [P2 order](interrupted-create-handoff-recovery-p2-interface-review.md:41)). The [current lease](../../src/core/task-persistence/parentHandoffFence.ts:65) and [host intake port](../../src/core/task-persistence/recoveryIntake.ts:13) have no enforced nesting/atomic-writer coordinator ([P2 enforcement finding](interrupted-create-handoff-recovery-p2-interface-review.md:43)).

## Exit disposition and scope

**P2 exit BLOCKED:** durable host binding/atomic fenced-storage adapter, full writer/reader participation and authoritative lineage/child/API evidence, safe storage/lock hardening and separate-host stale-owner/crash proof remain missing ([P2 review](interrupted-create-handoff-recovery-p2-interface-review.md:91), [P2 phase matrix](interrupted-create-handoff-recovery-p2.md:76)). **P3 exit BLOCKED:** exact all-or-nothing attachment lifetime, protected journal/blob durability, later-state receipt replay, persisted UI receipt/queue edit-cancel/question ownership and real reload/crash/race integration remain missing ([P3 review](interrupted-create-handoff-recovery-p3-interface-review.md:67), [P3 phase matrix](interrupted-create-handoff-recovery-p3.md:59)). P4 and later gates, live repair and exactly-once remote delivery are not established ([P1 remaining gates](../architecture/interrupted-create-handoff-recovery-p1-contract.md:57)).
