# P3 revised direct-intake target-interface review

**Date:** 2026-10-05 UTC. **Verdict: AGREE with the revised target interface, not current implementation.** This is a read-only design comparison, not P3 owner sign-off, P1 approval, an implementation exit, or authorization for live recovery. The [revised P1 contract](../architecture/interrupted-create-handoff-recovery-p1-contract.md:3) remains UNAPPROVED and dependent exits remain BLOCKED.

## Reviewed boundary

- **Entry and authority:** Manually stop the development queue and host, prove the previous capable host and in-flight work have exited, restart a verified loaded build at the canonical parent root, and establish fresh exact-action provenance. Only a newly sent DIRECT message to the interrupted parent can enter recovery; a committed child or unknown provenance blocks error resolution. Question-ID ownership takes precedence. See [manual sequence](../architecture/interrupted-create-handoff-recovery-p1-contract.md:5), [discriminator](../architecture/interrupted-create-handoff-recovery-p1-contract.md:13), and [three-way classification](../architecture/interrupted-create-handoff-recovery-p1-contract.md:31).
- **P2/P3 handoff:** P2 issues and durably records the immutable action generation from authoritative lineage/action evidence and supplies the guarded version-2 journal boundary under scoped host/root authority. P3 assigns and retains the random direct submission ID and exact input, resolves every attachment all-or-nothing, durably writes protected text and ordered image bytes, and verifies authoritative read-back of those exact bytes and the journal before emitting an intake receipt. See [binding](../architecture/interrupted-create-handoff-recovery-p1-contract.md:16), [journal and digest](../architecture/interrupted-create-handoff-recovery-p1-contract.md:21), and [protected storage](../architecture/interrupted-create-handoff-recovery-p1-contract.md:23).
- **Identity compatibility:** The version-1 fixed-order submission digest preimage, including binding, submission ID, origin, timestamp, text and ordered canonical image data URIs, is unchanged. The new journal uses schema version 2 and monotone revision; the original receipt's accepted version remains 1. A schema-version-1 journal is not silently interpreted as version 2. See [canonical identity](../architecture/interrupted-create-handoff-recovery-p1-contract.md:22).
- **Receipt/restart:** Look up an already accepted exact ID before classifying new intake; verify original binding, digest, protected payload bytes and later-stage correlation, then replay the original receipt after restart or action repair without new acceptance, API turn or loop. Retain a failed or unacknowledged direct draft; clear only the unchanged submission after its matching receipt. Receipt proves durable intake, not provider delivery. See [receipt rules](../architecture/interrupted-create-handoff-recovery-p1-contract.md:15), [later-state replay](../architecture/interrupted-create-handoff-recovery-p1-contract.md:17), and [uncertain delivery](../architecture/interrupted-create-handoff-recovery-p1-contract.md:34).

## Exact conflicts with the superseded addendum

1. The [old fenced-capability target](interrupted-create-handoff-recovery-p3-target-interface-addendum.md:11) requires separate fence-generation and owner-token capabilities and atomic lease-checked mutations; its [lock-order target](interrupted-create-handoff-recovery-p3-target-interface-addendum.md:27) mandates an outer interprocess fence and peer-writer coverage. The revised contract instead requires proved manual prior-host termination, verified host/root authority and scoped serialization; a cross-host fencing service, lease epoch and global ordinary-writer audit are not mandatory. A conflicting capable writer or unproved termination still blocks this exact recovery. See [scoped authority](../architecture/interrupted-create-handoff-recovery-p1-contract.md:28) and [no mandatory fence](../architecture/interrupted-create-handoff-recovery-p1-contract.md:29).
2. The [old queue target](interrupted-create-handoff-recovery-p3-target-interface-addendum.md:23) requires adopting an existing queued item's ID, time, order and payload before claim. The revised contract forbids using an old queued item as the recovery trigger, claiming/removing it or promising restoration of an in-memory item across the stop. Any item that survives stays under ordinary queue ownership; it is not silently consumed. Future queued recovery needs a separate review. See [direct-only discriminator](../architecture/interrupted-create-handoff-recovery-p1-contract.md:13) and [superseding scope](../architecture/interrupted-create-handoff-recovery-p1-contract.md:36).
3. The [old addendum's agreement](interrupted-create-handoff-recovery-p3-target-interface-addendum.md:3) is for its former cross-host/direct-plus-queued target and cannot be carried forward as revised P3 owner sign-off. The [P1 revision gate](../architecture/interrupted-create-handoff-recovery-p1-contract.md:65) explicitly requires new review and agreement.
