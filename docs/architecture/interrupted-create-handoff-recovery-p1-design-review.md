# Revised P1 manual-stop/fresh-direct design review

**Verdict: DISAGREE with the written contract as it stands.** This is a read-only design finding, not implementation PASS, S1 approval, recovery-tech-lead approval, or permission for live repair. The manual-stop/restart and fresh-DIRECT approach is not rejected in principle. The revised P1 remains UNAPPROVED and its historical reviews do not approve this target ([P1 status](interrupted-create-handoff-recovery-p1-contract.md:3), [P1 revision gate](interrupted-create-handoff-recovery-p1-contract.md:65), [S1 decision rule](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:19)).

## Findings and required contract corrections

1. **Child provenance: three labels, incomplete negative-proof procedure.** P1 distinguishes committed child, no attributable committed child with complete negative provenance, and unknown; it correctly rejects an empty transient directory as proof in either direction ([P1 classifier](interrupted-create-handoff-recovery-p1-contract.md:31)). The incident requires action-scoped examination of parent child IDs, child metadata, root lineage, other provider/task registries and handoff intent, with attribution of transient directories by timestamp and available metadata; missing or invalid readers and ambiguous provenance must block ([incident predicate](interrupted-create-handoff-recovery-analysis.md:22)). **Correction:** enumerate authoritative readers and how each establishes action-specific attribution or complete negative coverage, including identity/ordering against previously committed children, missing records, conflicting evidence and unavailable readers. Define fixture outcomes for committed, completely negative and unknown. Do not treat “no recorded child” alone as complete negative proof ([S1 warning](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:17)).

2. **Previous-host exit and loaded build/root: correct gates, insufficient evidence recipe.** P1 requires manual queue and host stop; actual predecessor exit and termination of in-flight writes/starts; loaded build/version, host identity and canonical resolved parent root verification; a socket, queue discipline or local mutex alone is insufficient ([P1 host authority](interrupted-create-handoff-recovery-p1-contract.md:28), [P1 restart](interrupted-create-handoff-recovery-p1-contract.md:34)). The incident snapshot did not verify a later live Insiders host or loaded fix, and its global storage root must be rechecked ([incident observations](interrupted-create-handoff-recovery-analysis.md:5), [incident host caveat](interrupted-create-handoff-recovery-analysis.md:7)). **Correction:** prescribe a bounded, recordable operator check identifying the predecessor process, confirming its actual exit and no surviving capable write/start, and identifying the restarted host's loaded build and resolved canonical parent root/configuration. Specify mismatch/unknown failure and revalidation before dependent mutation or restart. Neither intent to stop nor a distinct socket constitutes proof ([S1 operator boundary](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:7), [S2 check contract](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:25)).

3. **Exact-action exclusion: specified intent, missing atomic conflict boundary.** P1 calls for per-parent serialization, fresh stage-specific checks, and conditional repair, and acknowledges a process-local mutex cannot exclude another process ([P1 exclusion](interrupted-create-handoff-recovery-p1-contract.md:28), [P1 mutation checks](interrupted-create-handoff-recovery-p1-contract.md:29), [P1 repair](interrupted-create-handoff-recovery-p1-contract.md:33)). It does not identify how capable same-parent child prepare/commit/start or ordinary/startup writes to the exact action, child provenance or correlated API/metadata are excluded between a check and the repair write. Sequential file locks are not automatically a transaction ([incident concurrency](interrupted-create-handoff-recovery-analysis.md:16)). **Correction:** name the competing exact-action writers and the shared exclusion/conditional-write boundary, lock order and fail-closed behavior if a capable writer bypasses it; test write-after-check without requiring a global lock or blocking unrelated questions ([S2 exclusion](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:25), [S3 hostile cases](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:33), [dependency](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:50)).

4. **Surviving queued item: material conflict with the selected S1 target.** P1 says not to claim, remove, or promise survival of the pre-stop queued item but does not forbid accepting a fresh direct recovery for the same action while that item survives ([P1 selected sequence](interrupted-create-handoff-recovery-p1-contract.md:9), [P1 intake boundary](interrupted-create-handoff-recovery-p1-contract.md:13), [P1 queue fault](interrupted-create-handoff-recovery-p1-contract.md:53)). S1 explicitly defers only that recovery until the user resolves a surviving same-parent queued request through ordinary queue controls, to avoid double delivery; a newly queued message must not masquerade as DIRECT ([S1 safety](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:7), [P3 delta](../../../../.roo/interrupted-create-handoff-recovery-p2-feasibility-phases.md:43)). **Correction:** require a fresh same-parent/same-action queue check and deferral before accepting direct recovery, preserve ordinary ownership, and recheck at the recovery boundary; do not block unrelated queues or claim restoration of a lost item.
